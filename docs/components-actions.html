Actions

Things people press. Buttons do something, links go somewhere. css/components/actions.css

Button Atom components/actions.css

Use

  • <button> for actions, <a class="button"> to go somewhere.
  • One primary or accent button per view.
  • Label with a verb that says what happens.
  • Icon-only buttons need aria-label.

Don't

  • Use a <div> with a click handler.
  • Put accent and primary side by side.
  • Disable a submit button to hide errors; show the errors instead.

Modifiers

  • --secondary, --accent, --danger
  • --small, --icon, --block, --link
  • aria-busy="true" while working

Button group Molecule components/actions.css

Cancel

Use

  • Primary action first, then secondary, then a plain link to cancel.
  • --joined with aria-pressed for a view switch.

Don't

  • Put more than three actions in one group.
  • Use a joined group for actions that are not alternatives.

Back

Use

  • Top of each page in a multi-page form, above the h1.
  • Link to the previous step, so it works without history.

Don't

  • Use it on the first page of a flow, or with a sticky header that has its own back.

Exit this page

Use

  • Only for services where someone may be in danger if seen using them.
  • Add data-exit-page to the link: contour.js then also exits when Shift is pressed 3 times, and wipes the page first.
  • Explain the button and the Shift shortcut on the first page.

Don't

  • Use it on ordinary services. It frightens people.
