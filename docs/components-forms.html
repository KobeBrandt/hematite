Forms

Ask one thing at a time. Every control has a visible label, a 2.75rem target and an edge of 3:1 or more. css/components/forms.css

Text input and field Molecule components/forms.css

We only use this to send your confirmation. Error: enter an email address with a domain, like name@example.com

Use

  • A visible <label> on every control (3.3.2).
  • Hints and errors linked with aria-describedby; the error goes above the input.
  • autocomplete on personal data (1.3.5).
  • Size the box to the answer with --w2, --w4, --w10, --w20.

Don't

  • Use placeholder text as the label.
  • Show an error with a red border alone. Start the message with "Error".
  • Use type="number" for codes or card numbers; use inputmode="numeric".

States

  • .field--error adds the red side bar.
  • aria-invalid="true" gives the field a red edge, the same width as every other field, and a faint red fill.
  • readonly and disabled are dashed.

Textarea and character count Molecule components/forms.css

Do not include personal or financial information. You can enter up to 120 characters

Use

  • A character count only when there is a real limit.
  • Let people type past the limit, then show the error; pasting and editing is easier than being cut off.

Don't

  • Use maxlength: it silently cuts pasted text.
  • Announce the count on every keystroke (hematite.js waits for a pause).

Add textarea--auto to let the box grow with its text, from 4 to 12 lines, using field-sizing: content. Browsers without it show a normal resizable textarea.

Select Atom components/forms.css

Use

  • Only when there are too many options for radios (about 7 or more).
  • A sensible default, or an empty first option with a label like "Choose a country".

Don't

  • Use it for 2 to 5 options: radios show them all at once.
  • Submit on change (3.2.2).

Checkboxes and radios Molecule components/forms.css

Send me
How should we contact you?
Have you been here before?

Use

  • Radios when people pick one, checkboxes when they pick any number.
  • A <fieldset> and <legend> around every group (1.3.1).
  • .choices--inline only for two short options like Yes / No.

Don't

  • Pre-select a radio unless one answer really is the default.
  • Use a single checkbox for "I agree" when the user has no real choice.

Choice tiles Molecule components/forms.css

Choose a slot length

Use

  • A few choices that each need a short explanation.
  • The whole tile is the click target.

Don't

  • Use tiles for long lists; they take a lot of space.

Date input Molecule components/forms.css

What is your date of birth? For example, 27 3 1990

Use

  • Three boxes for dates people know (birth, passport issue).
  • Native type="date" only for picking a near date, like an appointment.
  • Accept "3", "03" and month names like "mar".

Don't

  • Use three selects for day, month, year.
  • Use a date picker for a birth date: scrolling back 40 years is slow.

Prefix and suffix Molecule components/forms.css

€
kg

Use

  • For units and fixed parts.
  • Say the unit in the label too; the affix is hidden from screen readers.

Don't

  • Put essential instructions in the affix.

Search Molecule components/forms.css

Use

  • role="search" on the form, and a label (hidden is fine here).
  • Keep the query in the box on the results page.

Don't

  • Search as you type without telling screen readers how many results there are.

Password input Molecule components/forms.css

Use

  • A Show button so people can check what they typed.
  • autocomplete="new-password" on sign-up, current-password on sign-in.
  • Allow paste (3.3.8).

Don't

  • Ask people to type the password twice; Show does the same job.
  • Set rules like "one capital letter". Ask for length instead.

File upload Atom components/forms.css

JPG or PNG, smaller than 10 MB

Use

  • Native <input type="file">: drag and drop and keyboard come with it.
  • State the formats and size limit in the hint.

Don't

  • Only accept upload when people could just as well type the answer.

Range slider Atom components/forms.css

10 km

Use

  • Only when an approximate value is fine.
  • Show the value next to it.

Don't

  • Use it when people need an exact number; offer a text input (2.5.7).

Combo box Molecule components/forms.css

Start typing, then pick from the list

Use

  • Native <datalist>: suggestions, but any text is still allowed.
  • For long lists where people know the answer (towns, countries).

Don't

  • Build a custom ARIA combobox unless you will test it with screen readers.

Error summary Organism components/forms.css

There is a problem

  • Enter an email address with a domain, like name@example.com
  • Date of birth must include a day

Use

  • At the top of the page after a failed submit, above the h1.
  • Same wording as the error next to the field, each linking to the field.
  • data-error-summary moves focus to it on load; add "Error: " to the page title.

Don't

  • Show it while people are still typing.
  • Use it for a single field on a short form? Still use it: it is the first thing a screen reader hears.
