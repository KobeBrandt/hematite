Patterns

Components are the parts; patterns are how to combine them for a task people do again and again. These follow the research published by GOV.UK, the Vlaanderen design system and the US Web Design System.

Names

Ask for a name

  • One "Full name" field unless you really need parts. Not everyone has a first and last name.
  • autocomplete="name", spellcheck="false".
  • Allow any characters, including accents, hyphens and apostrophes.

Addresses

Ask for an address

  • Separate fields for street, number, postcode and town, with autocomplete on each.
  • Postcode box sized to a postcode (input--w4).
  • Do not make the second address line required.

Dates

Ask for a date

  • Date input (three boxes) for known dates; native date picker for near dates.
  • Hint with an example in the expected order: "For example, 27 3 1990".
  • Error messages that say which part is missing.

Email

Ask for an email address

  • type="email", autocomplete="email", spellcheck="false".
  • Say why you need it in the hint.
  • Do not ask for it twice; show it back on the check answers page.

See the component

Phone numbers

Ask for a phone number

  • type="tel", autocomplete="tel".
  • Accept spaces, brackets and +32.
  • Say if you will call, text or both.

Passwords

Ask for a password

  • Password input with a Show button.
  • Ask for length (at least 12 characters), not symbol rules.
  • Allow paste and password managers (3.3.8).

See the component

Question pages

One thing per page

  • One question per page, the label or legend is the h1.
  • A back link above, one Continue button below.
  • Narrow container (.container--narrow).

Validation

Recover from errors

  • Validate on submit, not while people type.
  • Error summary at the top, error message above each field, "Error: " in the title.
  • Say what went wrong and how to fix it: "Enter a date in the past", not "Invalid date".

See the component

Check answers

Check answers before sending

  • Summary lists, one per section, each with Change links.
  • Change links return to the question, then back to this page.
  • The send button says what happens: "Accept and send".

Many tasks

Complete multiple tasks

  • A task list when a transaction has several parts people can do in any order.
  • Status in words: Completed, Incomplete, Cannot start yet.
  • Save progress automatically.

Open the template

Start

Start using a service

  • A start page says what the service does, who can use it and what people need.
  • One green-for-go equivalent: the accent "Start now" button.

Open the template

Confirmation

Confirmation page

  • A panel with the reference number as the h1.
  • What happens next, as a process list.
  • A link to give feedback.

Open the template

Error pages

When things go wrong

  • 404: say the page was not found and how to fix the address.
  • 503: say when the service will be back and what to do meanwhile.
  • 500: say it is our fault, whether answers were saved, and who to contact.
  • No technical codes or jokes.

Open the template

Navigation

Navigate a service

  • Header navigation for sections, breadcrumb on deep pages, side navigation for apps.
  • Back links in form flows, not breadcrumbs.
  • Skip link on every page.

Cookies

Cookie consent

  • Cookie banner with equal accept and reject buttons.
  • A cookies page that lists every cookie and lets people change their choice.
  • No analytics before consent.

Leaving quickly

Exit a page quickly

  • Exit this page button on services about abuse or other danger.
  • Explain it once; it also works with Shift pressed 3 times.

Writing for the interface

Words are part of the design. Write from the reader's side of the screen.

RuleWriteNot
Buttons say what happensSend bookingSubmit
Errors say how to fix itEnter a date in the pastInvalid date
Errors do not blameEnter your postcodeYou forgot your postcode
Links say where they goRead the cookie policyClick here
Plain wordsHelp, start, buyAssistance, commence, purchase
